# Налаштування Radar: формати файлів

Програмі потрібні три файли. У Linux-версії вони лежать у `~/.config/radar/`, у веб-версії — у
`config/radar/` цього репозиторію. Формати однакові. Якщо файлу немає, його створює
`ensure_config()`: видання й теми копіюються з `radar/defaults/`, а параметри беруться з
`DEFAULT_SETTINGS` у `radar.py`.

Усі файли мають кодування UTF-8.

---

## 1. `sources.json` — видання

JSON-масив об'єктів. Порядок у масиві — це порядок видань на сторінці й пріоритет у сюжеті, коли
кілька видань опублікували новину в одну хвилину.

### Поля

| Поле | Тип | Обов'язкове | Що означає |
|---|---|---|---|
| `name` | рядок | так | Назва, яку видно на сторінці. Має бути унікальною: за нею новини прив'язуються до видання в базі. |
| `url` | рядок | так | Сторінка видання. Для `html` її Radar і читає, для `rss` вона лише довідкова. |
| `type` | `"rss"` або `"html"` | так | Як отримувати новини. |
| `feeds` | масив рядків | для `rss` | Адреси RSS або Atom. Читаються всі, а якщо частина не відповідає, береться решта. |
| `enabled` | булеве | ні (`true`) | Вимкнене видання не завантажується й не показується у фільтрі. |
| `link_regex` | рядок (регулярний вираз Python) | для `html` | Які посилання на сторінці вважати новинами. |
| `link_contains` | рядок | ні | Залишити лише посилання, що містять цей текст. Корисно, коли стрічка спільна для всього видання. |
| `fallback_feeds` | масив рядків | ні | Запасні стрічки, коли сайт відповідає 401, 403 чи 429. Зазвичай Google News RSS. |
| `all_news` | булеве | ні | Брати **всі** новини видання без фільтра тем. |
| `all_news_topic` | рядок | ні | Тема, до якої відносити новини при `all_news`, наприклад «Криптовалюти». Якщо її немає, це «Усі новини видання». Такі видання рахуються в сюжеті з вагою 0,5. |
| `top_page` | булеве | ні | Шукати на сторінці `url` виділені редакцією новини (жирні, акцентні) і позначати їх «Важливо». |
| `top_feeds` | масив рядків | ні | Стрічки «головної сторінки» видання. Усе, що в них є, вважається важливим. |
| `top_categories` | масив рядків | ні | Рубрики (`<category>` у RSS), що означають важливу новину. |
| `via` | рядок | ні | Службова позначка, звідки взято стрічку (наприклад, «Google News»). Лише для показу у вікні. |
| `top_verify` | об'єкт `{require, reject}` | ні | Перед позначкою «Важливо» відкрити статтю: у HTML має бути рядок `require` і не має бути рядка `reject`. |

### Приклади

```json
{
  "name": "Економічна правда",
  "url": "https://epravda.com.ua/news/",
  "type": "rss",
  "feeds": ["https://www.epravda.com.ua/rss/view_news/"],
  "enabled": true,
  "top_page": true,
  "fallback_feeds": [
    "https://news.google.com/rss/search?q=site%3Aepravda.com.ua+when%3A1d&hl=uk&gl=UA&ceid=UA%3Auk"
  ]
}
```

```json
{
  "name": "Мінфін",
  "url": "https://minfin.com.ua/ua/news/",
  "type": "html",
  "link_regex": "/ua/\\d{4}/\\d{2}/\\d{2}/\\d+/?$",
  "enabled": true,
  "all_news": true,
  "top_page": true,
  "top_verify": {"require": "wrapper-authors", "reject": "youtube.com/embed"}
}
```

### Як додати видання

- **У вікні**: вкладка «Видання» → «Додати», вставити адресу сайту.
- **У терміналі**: `radar source add https://example.com [Назва]`.
- **У веб-версії**: відредагувати `config/radar/sources.json` на GitHub.

Перші два способи викликають `discover_source()`. Вона пробує по черзі:
1. RSS, указаний на сторінці (`<link rel="alternate">`);
2. типові адреси RSS;
3. читання посилань із самої сторінки (`type: "html"`);
4. пошук Google News `site:домен` для сайтів, що блокують автоматичні запити.

## 2. `topics.txt` — теми

Звичайний текст, один запис на рядок.

```
# коментар
[Назва групи]
Назва теми: ключ1, ключ2, ключ3
```

- `[Назва групи]` починає групу. Групи стають розділами у вкладці «За темами» на сторінці.
  Теми до першої групи потрапляють в «Інше».
- Новина підходить темі, якщо знайдено **хоч один** ключ.
- Якщо ключів немає (лише назва теми), шукається сама назва.
- Великі й малі літери не важливі, апострофи `’ ʼ ' \`` вважаються однаковими.

### Синтаксис ключа

| Запис | Що знаходить | Як реалізовано |
|---|---|---|
| `кредит` | початок слова: «кредити», «кредитний» | у кінці слова відкидаються голосні (`stem`), далі `\w*` |
| `облікова ставка` | фразу в будь-якій формі: «обліковій ставці» | так само для кожного слова, між словами будь-які розділювачі |
| `=євро` | лише точне останнє слово: «євро», але не «Європа» | `=` на **початку** ключа робить точним останнє слово |
| `банк & кібер` | обидва ключі в одному тексті, у будь-якому порядку | ` & ` обов'язково з пробілами |
| `=мсб & кредит` | `=` можна ставити на початку кожної частини з `&` | |

Типові помилки:
- `=` у середині ключа (`на =роботі`) не працює. Пишіть `=на роботі`.
- `&` без пробілів (`m&a`) — це звичайний текст, а не «і». Так і задумано, щоб працювало `M&A`.
- Короткі ключі на кшталт `ставк` знаходять багато зайвого, тому їх краще поєднувати через `&`.

### Де шукаються ключі

1. У заголовку: в українському перекладі й в оригіналі.
2. У першому абзаці новини (якщо в `settings.json` `match_summary: true`). Тема з абзацу додається,
   лише коли абзац збігся щонайменше з **двома** різними темами.

Після зміни файлу новини за період `report_days` автоматично переперевіряються на наступному
запуску.

Зараз у файлі 189 тем у 14 групах.

## 3. `settings.json` — параметри

| Ключ | Тип | За замовчуванням | Що означає |
|---|---|---|---|
| `schedule_mode` | `"interval"`, `"times"`, `"off"` | `"interval"` | Як часто оновлювати (лише Linux) |
| `interval_minutes` | ціле | `60` | Інтервал для `interval`, мінімум 5 |
| `times` | масив `"ГГ:ХХ"` | `["08:00","13:00","19:00"]` | Час для `times` |
| `report_days` | ціле | `3` | За скільки днів показувати новини на сторінці |
| `max_age_hours` | ціле | `36` | Новіші за цей вік публікації вважаються свіжими. Старіші записуються в базу, але не показуються. |
| `match_summary` | булеве | `true` | Шукати теми також у першому абзаці |
| `notifications` | булеве | `true` | Сповіщення про свіжі новини після кожного оновлення (лише Linux) |
| `digest_enabled` | булеве | `true` | Ранковий підсумок — одне сповіщення з головним за ніч (лише Linux) |
| `digest_time` | `"ГГ:ХХ"` | `"09:00"` | Час ранкового підсумку |

Застарілі ключі зі старіших версій (`translate`, `important_min_outlets`, `notify_when_empty`)
`load_settings()` ігнорує й видаляє.

У веб-версії діють лише `report_days`, `max_age_hours` і `match_summary`. Розклад там задає
`cron` у `.github/workflows/radar.yml`.

Після зміни розкладу в Linux-версії треба виконати `radar schedule` (або натиснути «Зберегти» у
вікні), щоб перезаписати таймери systemd.
