# Розробка Radar

Як запустити, змінити, перевірити й випустити програму. Архітектура описана в `ARCHITECTURE.md`,
формати файлів — у `CONFIGURATION.md`.

## 1. Підготовка

```bash
git clone https://github.com/goloborodko-yaroslav/radar.git
cd radar
python3 --version        # потрібно 3.10+
```

Встановлювати пакети не треба: Radar використовує лише стандартну бібліотеку Python. Для вікна
налаштувань у Debian, Ubuntu чи Mint потрібен пакет `python3-gi` з GTK 3. У Linux Mint він уже є.

## 2. Запуск в ізольованій теці (не чіпаючи робочу копію)

Усі шляхи беруться зі змінних `XDG_CONFIG_HOME` і `XDG_DATA_HOME`. Якщо їх перевизначити, можна
працювати з окремими налаштуваннями й базою:

```bash
export XDG_CONFIG_HOME="$PWD/config"      # налаштування веб-версії з репозиторію
export XDG_DATA_HOME="$PWD/.data"         # база й сторінка — у .data/ (у .gitignore)
python3 radar/radar.py run --no-notify    # один повний цикл, ~1–3 хв
python3 radar/radar.py status
xdg-open .data/radar/report.html          # або відкрити файл у браузері
```

Перший запуск триває довше: Radar дістає перші абзаци й перекладає все за останні дні. Журнал
пишеться в `.data/radar/radar.log`.

Корисні команди (повний список: `python3 radar/radar.py help`):

```
run [--no-notify] [--quiet]   оновити
open                          відкрити сторінку
gui                           вікно налаштувань
sources / source add URL      видання
topics / topic add "Т: к1, к2"
schedule 60 | 08:00 13:00 | off
notifications on|off
digest                        ранковий підсумок зараз
status
```

## 3. Як перевіряти зміни

Автоматичних тестів у проєкті поки немає. Нижче — перевірки, які варто робити вручну. Перші
кандидати на юніт-тести: `keyword_regex`, `match_topics`, `story_tokens`, `build_stories`,
`extract_lead`, `needs_translation`, `link_key`, `parse_feed`. Це чисті функції без мережі.

**Ключові слова.** Чи знаходить тема те, що треба:

```bash
python3 -c "
import sys; sys.path.insert(0, 'radar'); import radar
topics = radar.parse_topics(open('config/radar/topics.txt', encoding='utf-8').read())
print(radar.match_topics('НБУ знизив облікову ставку до 13%', topics))"
# ['НБУ', 'Облікова ставка НБУ']
```

**Сюжети.** Після зміни `build_stories` порівняйте кількість сюжетів і вибірку об'єднаних на тій
самій базі до й після. Спершу скопіюйте `radar.db`, щоб база була однакова.

**Сторінка.** Відкрийте `report.html` і перевірте всі три вкладки, пошук, фільтр видань,
«Сховати прочитані», світлу й темну тему системи та ширину телефона (~375 px).

**Вікно.** `python3 radar/radar_gui.py`: кожна вкладка, «Зберегти», додавання й видалення видання.

**Синтаксис.** `python3 -m py_compile radar/radar.py radar/radar_gui.py`.

## 4. Випуск

### Веб-версія

Будь-який push у `main`, що змінює `radar/`, `config/` або `.github/workflows/`, сам запускає
workflow `Radar`. За 1–3 хвилини він публікує нову сторінку. Хід видно у вкладці **Actions**.
Ручний запуск: Actions → Radar → **Run workflow**, або з терміналу:

```bash
gh workflow run radar.yml -R goloborodko-yaroslav/radar
```

Скинути базу хмарної версії: видалити кеші `radar-db-*` (Actions → Caches). Наступний запуск
створить нову.

### Linux-версія

```bash
sh radar/install.sh       # копіює програму в ~/.local/share/radar/app і ставить таймер
```

Повторний запуск `install.sh` оновлює програму, а налаштування користувача не перезаписує.
Видалення: `~/.local/share/radar/app/uninstall.sh`. Програма, база й таймери видаляються, а
`~/.config/radar` залишається. З `--all` видаляються й налаштування.

`radar/defaults/` містить видання й теми для **нової** установки. Якщо змінюєте набір за
замовчуванням, змініть і `config/radar/` (веб-версія), коли це потрібно.

## 5. Як зазвичай розширюють програму

**Нове видання з особливостями.** Спершу спробуйте обійтися полями `sources.json`
(`link_regex`, `link_contains`, `fallback_feeds`, `top_*`). Код змінюйте, лише коли полів бракує:
новий спосіб читання додається гілкою у `fetch_source()`, новий сигнал важливості — у
`editorial_signals()` або в кроці 2 `run()`.

**Новий спосіб перекладу** (наприклад, платний API). Замініть `google_translate()`. Функція
отримує текст із кількома рядками й має повернути переклад із тією самою кількістю рядків:
`translate_titles()` склеює заголовки через `\n`.

**Інша мова інтерфейсу.** Тексти інтерфейсу вписані прямо в код (`radar.py`, `radar_gui.py`,
`report_template.html`). Для перекладу їх спершу треба винести в окремий словник.

**Windows або macOS.** Ядро (`run`, сторінка) переносне. Винятки:
- `fcntl.flock` у `run()` — Unix-only. На Windows замініть на `msvcrt.locking` або файл-маркер.
- Таймери systemd (`install_timer`, `apply_schedule`) — лише Linux. На Windows підійде Task
  Scheduler, на macOS — launchd.
- Сповіщення через D-Bus (`notify_and_wait`) — лише Linux.
- Вікно GTK на інших системах складно поставити. Простіше обійтися веб-версією.

## 6. Відомі проблеми й ризики

| Проблема | Наслідок | Що можна зробити |
|---|---|---|
| Розклад GitHub Actions не гарантований: запуски затримуються або пропускаються, у нових репозиторіях можуть годинами не стартувати | сторінка оновлюється рідше, ніж задумано | зовнішній тригер `workflow_dispatch` (cron-job.org, таймер на ноутбуці з `gh workflow run`) |
| `translate.googleapis.com` (`client=gtx`) — неофіційний endpoint | може обмежити частоту або перестати працювати | Google Cloud Translation, DeepL API, LibreTranslate |
| Читання сторінок (`type: html`, `top_page`) залежить від верстки сайту | після редизайну видання новини чи позначки «важливо» зникнуть мовчки | стежити за `radar.log` і за кількістю новин від видання |
| Деякі сайти блокують запити з серверів (ЕП, LIGA з GitHub — 403) | у хмарі заголовки йдуть через Google News, без першого абзацу | `fallback_feeds`, або власний сервер з іншою IP |
| Reuters, FT, WSJ, Bloomberg закривають RSS або вміст | заголовки неповні, абзаців немає | лише заголовки — свідоме обмеження |
| Відбір за ключовими словами | можливі хибні збіги й пропуски | уточнювати `topics.txt`, поєднувати ключі через `&` |
| Стан «прочитано» живе в `localStorage` браузера | не синхронізується між пристроями | потрібен бекенд або синхронізація через обліковий запис |
| Сторінка веб-версії публічна (GitHub Pages) | будь-хто з посиланням бачить список | приватний репозиторій з Pages (платний план) або інший хостинг з авторизацією |

## 7. Стиль коду

- Один модуль ядра `radar.py`, розділений коментарями `# ----- розділ`. Функції короткі, без
  класів, де вони не потрібні.
- Коментарі й тексти українською, імена англійською.
- Лише стандартна бібліотека в ядрі. Нова залежність має вагомо окупатися, бо зараз програма
  ставиться без `pip`.
- Пишуть у базу `run()` і `digest()`. Єдиний виняток — перейменування видання у вікні: воно
  оновлює `items.source`, бо новини прив'язані до видання за назвою. Сторінка базу лише читає.
